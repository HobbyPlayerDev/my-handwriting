# my-handwriting - project notes for Claude Code

**my-handwriting** teaches Claude a person's handwriting - made mainly for Claude: a web app to capture
samples (every character several times) and to write any text with them (PNG/SVG/PDF), plus the Claude
skill `/my-handwriting` (Python script) that lets Claude write documents in that handwriting. Public on GitHub (MIT). This file is published too: **no personal data** (names,
e-mail addresses, local paths) - that belongs in Claude's memory.

Everything in the repository is **English** (folders, file names, comments, docs). The interface is
translated (6 languages); Python messages are English/German via `L("deutsch", "english")`.

More: `README.md`, `docs/CONCEPT.md` (full concept, data format, limits, ideas), `docs/PUBLISHING.md`
(release checklist), `CHANGELOG.md`, `skill/my-handwriting/SKILL.md`, `NOTICE.md`.

## Hard rules
- **No build step, no dependencies** in the web part (classic `<script>` files, one stylesheet, no
  external fonts/libraries). Must work by double-click (`file://`) **and** over https (GitHub Pages).
- Python: standard library only, Python ≥ 3.8; Pillow only optional (PNG, `tests/make_fixture.py`).
  The skill folder `skill/my-handwriting/` must stay self-contained (it is copied by `install`).
- **Never real handwriting sample files in the repository** (exports, `data/`, skill ZIPs). The README
  pictures `docs/example.png` + `docs/screenshot.png` show an example handwriting the owner wrote in the app. Tests use the synthetic samples of
  `tests/make_fixture.py`. `.gitignore` excludes `skill/my-handwriting/data/`, exports, `out/`.
- Data format `my-handwriting-glyphs` v1: only **extend**; old files must stay readable
  (`handschrift-glyphs` = old name, files without `scripts` = German).
- Kept identical in JS and Python (checked by `tests/py_test.py`): character groups
  (`js/charsets.js` ↔ `GROUPS`/`LANG_GROUPS`), `FALLBACKS`, `APPROX`, Markdown blocks
  (`parseBlock` ↔ `parse_block`), the standard handwriting (`js/fallback-font.js` ↔
  `scripts/fallback_font.json`, both generated by `tools/build_fallback_font.py`), `slug()` (app.js ↔ Python),
  the settings line labels (`SETTING_LABELS` in Python = the words of `js/lang/<code>.js`).
- `skill/my-handwriting/LICENSE` is a copy of `LICENSE` (MIT wants it in every copy, the ZIP included;
  py_test checks both are equal).
- **`js/skill-bundle.js` is generated** from `skill/my-handwriting/` by `tools/build_skill_bundle.py`:
  after every change in the skill folder run it (py_test and CI fail otherwise). The app builds the
  skill ZIP from it (`js/zip.js`, stored ZIP), so Claude gets exactly the shipped skill.
- Every new UI text: key in **all 6** files of `js/lang/` (`tests/i18n_test.js` checks completeness,
  placeholders, used keys). A new language: new file in `js/lang/`, script tag in `index.html`,
  entry in `sw.js` FILES, letters in `js/charsets.js` + `LANG_GROUPS` in Python.

### Storage: several handwritings
IndexedDB `my-handwriting` / store `kv`: `profiles` = JSON `{active, list: [{id, name, created, samples}]}`,
`state:<id>` = JSON `{savedAt, state}` per handwriting; localStorage keeps a copy of both
(`my-handwriting-profiles`, `my-handwriting-state:<id>`). Device settings outside: `my-handwriting-lang`
(interface language), `my-handwriting-pen`. Upgrades: no `profiles` yet → the single `state` key of 1.0
(or the old name `handschrift-erfassung`) becomes handwriting 1; old keys are left untouched.
Default names ("Handwriting 2") follow the interface language (`defaultNumber`). Delete and "reset
everything" keep the removed data in memory for the undo toast until the page is closed.
Skill: `data/glyphs.json` (default) + `data/glyphs-<slug>.json`; the name is read from the file's `name`.

### State (`state`, saved as `{savedAt, state}`)
`glyphs` {char: [{id, created, strokes: [[x,y,…]], dev}]}, `settings` {target, mode char|round, penOnly
auto|on|off, custom, groups {id: false = off}, scripts [codes], template, templateAlpha, lang, fallbackFont,
realism (default true; exported as `claude.realism`),
claude {paper, size, color, page, align, variation 0-2 (shown as % = ×50); old files: lang - unused}, write {size, paper, page, color, align, variation, transparent,
text, markdown}}, `meta` {wizardDone, introSeen, lastExport, samplesAtExport, current, persistAsked,
claudeSet, migrated}. Device setting outside the state: `localStorage['my-handwriting-pen']`.

### Groups
Order: upper, lower, `lang-<code>` (selected languages), digits, punct, math, special, custom. A
character appears only in the first group that has it. Own characters are hidden only if a group
that is **on** shows them; `groupOf` prefers groups that are on.

### Characters without samples (`TS.plan` / `Typesetter.plan`)
Pass 1 with own samples only (FALLBACKS, accents; approximations from `APPROX` are skipped when the
font has the character). If anything is still missing and the font is on: the font's character
(`'f'`), else pass 2 composing with font parts. Case swap (scaled capital) only without the font.
`fontChars` / `font_chars` = characters that used the font (shown to the user).

### Realism (`realism` option, render.js ↔ Python)
Only when on (so output without it stays identical): per letter `realShape()` (width stretch, slant
jitter) and `tremor()` (two slow sine waves along the arc length); per line a slow size wave and a
height hop per word (new word = gap > 0.3); per stroke a pen-pressure factor with tapered start/end
(stroke split into 5 overlapping parts). The widths live in `pg.inkW` / `pg.ink_w` (one factor per
ink stroke, quantised to 0.05); all writers draw `inkGroups(pg)` / `ink_groups(pg)` = one path per width.

### Claude settings (`settings_line`)
`render` prints first (and puts into the JSON report as `settings_line`) one line with every setting
in the app's words and in `claude.lang`; SKILL.md tells Claude to start its answer with it. Settings
come from: command line > `settings.claude` of the exported file > `CLAUDE_DEFAULTS`. Irregularity:
`--irregularity` 0-100 % = `variation` × 50 (the app's sliders show the same %).

## Known pitfalls
1. `python -m http.server` serves `.js` as `text/plain` on Windows → the service worker does not
   register locally ("unsupported MIME type"). Normal scripts still run. No problem on GitHub Pages.
2. Browser preview in the background: screenshots can be **stale**. Read state with `javascript_tool`;
   check pixels with `getImageData`, or render a PNG with the Python script and look at it.
3. PDF in the browser without `simplify` was 3.7 MB for 3 pages → Douglas-Peucker (0.002) + FlateDecode
   (`CompressionStream`): 233 KB. Cut off the old xref table before rebuilding it.
4. Dynamic i18n keys (`'names.' + ch`, `'wiz.how' + i`, `'paper.' + v` …) are checked separately in
   `i18n_test.js` - add new dynamic prefixes there.
5. Windows console: Python output through a pipe used cp1252 and crashed on "✓" → `_fix_console()`.
6. Bigger buttons never via `@media (pointer: coarse)` (wrong on touch laptops) but the class `touch-ui`.
7. Hershey data: the last record of `futural.jhf` is a filled block (DEL), and `, . ; :` sit 3 units
   too high - both fixed in `build_fallback_font.py`. After any change run it and commit both outputs
   (CI fails otherwise).
8. Two-pass planning must not recurse: only the top call (`own` undefined/None) runs both passes.
9. The overview is rebuilt on every change: never keep references to `#addChars` across `renderAll()`.
10. Python patch scripts with backslashes (Windows paths, regex) never via a Bash heredoc - write them
    with the Write tool (backslashes get mangled).
11. Regular expressions inside Python patch strings lose backslashes (a regex in app.js lost its `\`
    and broke the whole file) - write such lines with the Edit tool and run `node --check` after every patch.
12. Overview groups are rebuilt on every change; their open/closed state lives in `ovOpen` (memory only).
13. app.js has a local `history` (undo snapshots) that hides the browser's `history`: always write
    `window.history` (pushState silently failed inside try/catch). `i18n_test.js` checks it.
14. Dialogs and the back button: `openModal` pushes one entry `{myHandwritingDialog:1}` (only if not
    already on one), `closeModal` steps back after a 0 ms delay (another dialog may open in the same
    step), our own step back is ignored via `selfBack`. Close dialogs only with `closeModal(id)`.
15. Text set via `data-i18n` replaces the whole element content: put icons next to a `<span data-i18n>`,
    never inside an element that has `data-i18n` itself.
16. Never use the CSS shorthand `inset` (old Safari): write top/right/bottom/left.
17. Selects are replaced visually (`js/ui-select.js`): in tests set `sel.value = …` and dispatch `change`, or
    click `sel._uiBtn` and then `.sel-menu [data-i]`. Clicking the hidden select does nothing.
18. Phones fire `resize` when the address bar moves: close menus only when the **width** changes.
19. A hidden/background preview pane pauses animations: screenshots show half-faded dialogs. Check
    classes/state with javascript instead of trusting such screenshots.
20. Document defaults live in `settings.claude` (exported for the skill) **and** are copied to
    `settings.write` by `setDocDefaults`; `claude.lang` is no longer chosen - the export writes the
    interface language. The very first setup (`firstSetup()`) has no × and ignores Esc/back.
21. A CSS rule with `display:flex/grid` beats the `hidden` attribute: add `.x[hidden]{display:none}` for
    every such class that is toggled with `hidden` (the install notes showed although hidden).
22. `tests/ui_audit.js` runs on the active profile and may leave things behind (custom characters,
    document defaults): every check must work on a second run too.
23. Headless Edge/Firefox scripts (screenshot, icons, Firefox check) hang without an error when their
    debugging port is still taken by a leftover browser: use a fresh port and `timeout`.
24. Douglas-Peucker keeps only the end points of a straight line, so the kerning profiles (`profiles()`)
    must fill in the bands between two points - otherwise letters slid into straight stems (BB, DD,
    AA). The synthetic fixture (horizontal scan lines) never showed it: `render_test.js` / `py_test.py`
    have a B with a two-point stem. The letter gap has a floor of min(0.1, tracking) (pen ≈ 0.075).
25. "Fit to text" (`page: 'auto'`): each page gets the height of its own lines (`heightOf` /
    `height_of`), not of the longest page. Both bugs 24/25 showed only with a real export: to try the
    skill with real samples, write the output into `out/` only (ignored) and never commit it.

26. `TS.charsToItems` joined the whole rest of the line for every character (multi-character keys) →
    one long paragraph was quadratic (67 pages: 95 s, the write dialog froze). Look ahead only as far
    as the longest key. Time long single paragraphs, not only many short lines.
27. Never let an empty state replace saved samples: if `readState` finds nothing for a handwriting
    whose profile record says `samples > 0` (IndexedDB slow/timeout, read error), `checkLoaded` marks
    it `unreadable` and `saveNow` refuses to write it until reload. Test: delete `state:<id>` in IDB +
    localStorage, reload → toast `toast.loadFail`, nothing written; put the copies back.
28. `buildPages` sanitises size/variation/margin/width: NaN from an edited file became NaN coordinates.
