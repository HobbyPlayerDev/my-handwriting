# my-handwriting - project notes for Claude Code

**my-handwriting** teaches the computer a person's handwriting: a web app to capture samples (every
character several times) and to write any text with them (PNG/SVG/PDF), plus a Claude skill with a
Python script. Public on GitHub (MIT). This file is published too: **no personal data** (names,
e-mail addresses, local paths) - that belongs in Claude's memory.

Everything in the repository is **English** (folders, file names, comments, docs). The interface is
translated (6 languages); Python messages are English/German via `L("deutsch", "english")`.

More: `README.md`, `docs/CONCEPT.md` (full concept, data format, limits, ideas), `docs/PUBLISHING.md`
(release checklist), `CHANGELOG.md`, `skill/my-handwriting/SKILL.md`, `NOTICE.md`.

## Hard rules
- **No build step, no dependencies** in the web part (classic `<script>` files, one stylesheet, no
  external fonts/libraries). Must work by double-click (`file://`) **and** over https (GitHub Pages).
- Python: standard library only, Python ≥ 3.8; Pillow only optional (PNG, `tests/make_fixture.py`).
  The skill folder `skill/my-handwriting/` must stay self-contained (it is copied by `install`).
- **Never real handwriting samples in the repository.** Tests use the synthetic samples of
  `tests/make_fixture.py`. `.gitignore` excludes `skill/my-handwriting/data/`, exports, `out/`.
- Data format `my-handwriting-glyphs` v1: only **extend**; old files must stay readable
  (`handschrift-glyphs` = old name, files without `scripts` = German).
- Kept identical in JS and Python (checked by `tests/py_test.py`): character groups
  (`js/charsets.js` ↔ `GROUPS`/`LANG_GROUPS`), `FALLBACKS`, `APPROX`, Markdown blocks
  (`parseBlock` ↔ `parse_block`), the standard handwriting (`js/fallback-font.js` ↔
  `scripts/fallback_font.json`, both generated by `tools/build_fallback_font.py`).
- Every new UI text: key in **all 6** files of `js/lang/` (`tests/i18n_test.js` checks completeness,
  placeholders, used keys). A new language: new file in `js/lang/`, script tag in `index.html`,
  entry in `sw.js` FILES, letters in `js/charsets.js` + `LANG_GROUPS` in Python.

## Run and test
- Preview: `python -m http.server 5311 --bind 127.0.0.1` in the project folder (`.claude/launch.json`,
  config `my-handwriting`). If the preview tool reads another project's `launch.json`, add the same
  entry there with `--directory <project folder>`.
- `node tests/i18n_test.js` · `python tests/make_fixture.py out/fx.json` · `node tests/render_test.js out/fx.json`
  · `python tests/py_test.py` (builds its own fixtures, installs into a temp folder). CI: `.github/workflows/tests.yml`.
- Load test samples into the app: `fetch('out/fx.json')`, put it as a `File` into `#fileInput`
  (DataTransfer), dispatch `change`, click "Merge".
- Test hook: `window.MyHandwriting` (`state()`, `current()`, `setCurrent(ch)`, `groups()`, `openWrite()`,
  `lastBuild()`, `exportData()`, `addCustom(text)`, `penSeen()`, `strokes()`); `<html data-started="1">` after start.
- Pen tests: dispatch `PointerEvent`s with `pointerType: 'pen'` on `#pad` (barrel: `button 2, buttons 2`;
  eraser: `button 5, buttons 32`; hover: `pointermove` with `buttons 0` on `document`). Remove
  `localStorage['my-handwriting-pen']` first, otherwise palm rejection is already on.
- Skill without touching the real one: `install --dest <temp>`; never run `install` without `--dest`
  in tests (it writes to `~/.claude/skills`).

## Architecture
```
index.html                 page (no inline scripts), dialogs: wizard, help, export, import, write text, settings
css/app.css                colours as variables, .touch-ui = bigger buttons, phone ≤ 700 px
js/i18n.js                 I18N core: add(code, name, table), t(key, vars), apply(), browserLang(); English default
js/lang/<code>.js          one table per language (en is the reference)
js/charsets.js             Charsets: BASE (upper lower digits punct math special), LANG (special letters), CORE
js/fallback-font.js        generated standard handwriting (window.FallbackFont)
js/render.js               Render: GlyphSet (resample, smooth, simplify, outliers, cap, xh, slant), FontSet, Typesetter
                           (two-pass plan, fonts, accents, slash, fractions, kerning), parseBlock, layout, buildPages,
                           drawPage, toSVG, toPDF, toPDFBlob
js/app.js                  state + storage (IndexedDB 'my-handwriting' + localStorage copy, migration from the old
                           name), writing area, guide letter, pen handling, wizard, own characters, export/import,
                           write dialog, settings
sw.js                      offline (http/https only), network first, cache name = version
skill/my-handwriting/      SKILL.md, scripts/my_handwriting.py (render info check sheet install package),
                           scripts/fallback_font.json, NOTICE.md; data/ (user file, ignored)
tools/                     build_fallback_font.py, hershey/ (source font + license)
tests/                     i18n_test.js, render_test.js, py_test.py, make_fixture.py
```

### State (`state`, saved as `{savedAt, state}`)
`glyphs` {char: [{id, created, strokes: [[x,y,…]], dev}]}, `settings` {target, mode char|round, penOnly
auto|on|off, custom, groups {id: false = off}, scripts [codes], template, templateAlpha, lang, fallbackFont,
claude {lang, paper, size, color, page}, write {size, paper, page, color, align, variation, transparent,
text, markdown}}, `meta` {wizardDone, introSeen, lastExport, samplesAtExport, current, persistAsked,
claudeSet, migrated}. Device setting outside the state: `localStorage['my-handwriting-pen']`.

### Groups
Order: upper, lower, `lang-<code>` (selected languages), digits, punct, math, special, custom. A
character appears only in the first group that has it. Own characters are hidden only if a group
that is **on** shows them; `groupOf` prefers groups that are on.

### Characters without samples (`TS.plan` / `Typesetter.plan`)
Pass 1 with own samples only (FALLBACKS, accents; approximations from `APPROX` are skipped when the
font has the character). If anything is still missing and the font is on: the font's character
(`'f'`), else pass 2 composing with font parts. Case swap (scaled capital) only without the font.
`fontChars` / `font_chars` = characters that used the font (shown to the user).

## Known pitfalls
1. `python -m http.server` serves `.js` as `text/plain` on Windows → the service worker does not
   register locally ("unsupported MIME type"). Normal scripts still run. No problem on GitHub Pages.
2. Browser preview in the background: screenshots can be **stale**. Read state with `javascript_tool`;
   check pixels with `getImageData`, or render a PNG with the Python script and look at it.
3. PDF in the browser without `simplify` was 3.7 MB for 3 pages → Douglas-Peucker (0.002) + FlateDecode
   (`CompressionStream`): 233 KB. Cut off the old xref table before rebuilding it.
4. Dynamic i18n keys (`'names.' + ch`, `'wiz.how' + i`, `'paper.' + v` …) are checked separately in
   `i18n_test.js` - add new dynamic prefixes there.
5. Windows console: Python output through a pipe used cp1252 and crashed on "✓" → `_fix_console()`.
6. Bigger buttons never via `@media (pointer: coarse)` (wrong on touch laptops) but the class `touch-ui`.
7. Hershey data: the last record of `futural.jhf` is a filled block (DEL), and `, . ; :` sit 3 units
   too high - both fixed in `build_fallback_font.py`. After any change run it and commit both outputs
   (CI fails otherwise).
8. Two-pass planning must not recurse: only the top call (`own` undefined/None) runs both passes.
9. The overview is rebuilt on every change: never keep references to `#addChars` across `renderAll()`.
10. Python patch scripts with backslashes (Windows paths, regex) never via a Bash heredoc - write them
    with the Write tool (backslashes get mangled).
